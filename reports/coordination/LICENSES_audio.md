# DabAI audio-side commercial license audit

**This is not legal advice.** It is desk research from primary sources (LICENSE files, Hugging Face model cards and API metadata, GitHub READMEs and code, dataset pages), checked 2026-10-16/17. Have counsel sign off before shipping.

Verdicts: **YES** = code and weights licenses both allow commercial use, and no non-commercial sub-model is loaded at inference. **YES\*** = the files are permissive, but the training data is non-commercial or unclear (needs legal sign-off). **UNCLEAR** = no decisive statement found. **NO** = non-commercial, research-only, or no license.

To make the decision easier, YES\* is split into two kinds:
- **YES\*(U)**: the training data is *undisclosed*. The vendor publishes the weights under a permissive license with no non-commercial clause. This is the normal industry situation for Whisper, Qwen, and so on.
- **YES\*(NC)**: the model card itself *names* training sets that are research-only or non-commercial. This is the **same class as the FFHQ-trained restorers that the 2026-10-16 CLEAN-ONLY directive quarantined** ("YES\* is not clean enough for the user"). Under that directive, treat YES\*(NC) as not shippable unless the user or counsel decides otherwise.

Status: DONE (2026-10-17).

**Bottom line:** 1 x NO (HDEMUCS separation), 1 x YES\*(NC) (pyannote diarization stack), 1 x UNCLEAR (ffmpeg build, until checked). Clean: wav2vec2-base-960h and librosa are YES. YES\*(U): faster-whisper large-v3, Qwen2.5-7B, Chatterbox, Silero VAD.

## (b) Blockers and actions

1. **BLOCKER: HDEMUCS_HIGH_MUSDB_PLUS = NO.** No weights license, and it was trained on MUSDB18-HQ ("Other (Non-Commercial)") plus internal Meta songs. Quarantine `hdemucs_high_trained.pt` (from `~/.cache/torch/hub/checkpoints/`) with the same procedure as the face models. First test the pipeline without separation. If separation is needed, audit Spleeter's weights and training data, or use a commercial separator. Official Demucs (htdemucs / mdx_extra) has the same MUSDB problem.
2. **BLOCKER under the CLEAN-ONLY directive: pyannote diarization = YES\*(NC).** The weights are MIT / CC-BY, but segmentation-3.0 is trained on research-only sets (MSDWild, VoxConverse, DIHARD/LDC, REPERE, Ego4D) and the WeSpeaker embedding on VoxCeleb ("for research purposes"). This is the same class as the FFHQ restorers already quarantined. Decision for the user: (a) accept with counsel sign-off; (b) buy a pyannoteAI commercial license / API; (c) drop diarization (single-voice or manual speaker tags) or find a diarizer with clean data (needs a new audit; most speaker-embedding models are also VoxCeleb-trained). Also verify locally which embedding the 3.1 config loads (the official config.yaml is gated; WebFetch got 401).
3. **UNCLEAR: ffmpeg build.** Run `ffmpeg -version` on every server and image. If the product is ever shipped on-prem or desktop, use an LGPL build (no libx264 / x265 / fdk-aac). Server-side SaaS use of a GPL CLI is normally fine. H.264/AAC patent licensing is a separate question.
4. **Decision needed: are YES\*(U) items acceptable?** faster-whisper large-v3, Qwen2.5-7B (Apache), Chatterbox (MIT), and Silero VAD (MIT) have clean files but undisclosed training data. That is industry-standard, but strictly it is "unclear", so get one explicit user / counsel sign-off for the whole class.
