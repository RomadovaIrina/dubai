## Method

1. Input -> 25 fps CFR master (same ffmpeg call LatentSync uses), own audio extracted to 16 kHz mono.
2. Every frame classified with LatentSync's own `FaceDetector` (buffalo_l, det 512, RGB, filter w>=50 / h>=80 / 0.2<w/h<1.5 /
   score>=0.5): **VALID_FACE** passes the filter, **SMALL_FACE** a face exists but fails it, **NO_FACE** nothing detected.
3. Consecutive frames form segments. VALID_FACE segments >= 25 frames -> `LATENT_SYNC`; shorter valid runs, SMALL_FACE and
   NO_FACE -> `PASS_THROUGH`. Before LatentSync runs, each cut segment is re-encoded the way LatentSync's `read_video` does
   and re-checked with the same detector; rejected frames split the segment (depth <= 3); a LatentSync exception falls back
   to pass-through (`PASS_THROUGH_LS_FAILED`) instead of crashing.
4. Output re-assembled frame by frame from the master (LatentSync frames substituted in place), original audio stream-copied.
   Nothing is deleted, no timeline compression.
5. Manifest per video: start_s, end_s, frames, classification, action, bbox stats (median w/h, min/max h, score, centre).
6. SyncNet (upstream evaluator) only on cuts with action=LATENT_SYNC; N/A elsewhere.
7. `--crop-experiment` (SMALL_FACE): fixed ROI around the median face (pad 0.6 x face each side), upscaled so face height ~160 px,
   LatentSync on the ROI clip, downscaled and pasted back -> separate `facesync_XX_smallface_crop.mp4` + ROI preview clip.

Two bugs found on the way and fixed in the script: LatentSync feeds the detector **RGB** frames (cv2 gives BGR — classifying in
BGR flipped borderline 80-px faces and made LatentSync fail on split sub-segments), and verification must be done on the
frames LatentSync actually sees (its own extra re-encode). With both fixes 05 needed no splits and no fallback.
