## Side finding — CodeFormer changes geometry

Input 464x848 -> output 512x936 for every w, also with `-s 1`. Cause: `facelib/utils/face_restoration_helper.py`
`read_image()` unconditionally upscales any frame whose shorter side is < 512 so that the shorter side becomes 512
(464 -> 512, 848 -> 936); `--upscale` is applied on top of that. Not fixed here. Consequence: the restored video is not
pixel-comparable to the LatentSync output, and any downstream evaluation (0.8 SyncNet on final videos, FVD, size/bitrate)
sees an upscaled frame; the control run above shows SyncNet itself is insensitive to it (−0.01).

## Verdict

```text
0.7 verdict:
CLOSED — NO_STRICT_SAFE_WEIGHT
```

Under the strict policy no CodeFormer weight keeps SyncNet confidence ≥ 3.21. AV offset never worsens (0 -> 0 at every w).
The decision that follows is a project one, not a measurement one: either run the pipeline with CodeFormer disabled, or
agree a tolerance (e.g. ≥ −0.05 confidence / 0 frames would admit w = 0.9); both options are documented, no threshold was
invented here.
